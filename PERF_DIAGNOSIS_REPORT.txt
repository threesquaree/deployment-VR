问题症状：
  ✗ 输入参与者ID和语言后，VR场景严重卡顿
  ✗ 2D画面也严重卡顿
  ✗ Headset里scene看不清楚

根本原因 🎯 - 找到了！
═══════════════════════════════════════════════════════════════════════

在 GetEyeData.cs 中发现的罪魁祸首：

位置: GetEyeData.cs, 第175和199行

问题代码:
┌──────────────────────────────────┐
│ textWriter.AutoFlush = true;   ❌│
│ eye120Writer.AutoFlush = true; ❌│
└──────────────────────────────────┘

═══════════════════════════════════════════════════════════════════════

详细问题分析
═══════════════════════════════════════════════════════════════════════

1️⃣  AutoFlush = true 的灾难性影响:
   
   当 AutoFlush = true 时，每次 WriteLine() 都会：
   ├─ 立即 Flush 到磁盘
   ├─ 同步等待磁盘I/O完成
   └─ 阻塞主渲染线程 ❌❌❌

2️⃣  执行频率超高:

   Update() 中的数据写入:
   ├─ Update() ≈每秒120次（眼动追踪频率）
   │  └─ 每次都同步写入磁盘
   │
   ├─ eye120Writer (120 Hz SRanipal stream)
   │  └─ 每次都同步写入磁盘
   │
   └─ 结果：每秒200-240次磁盘同步写入 ❌

3️⃣  磁盘I/O延迟阻塞渲染:

   典型磁盘性能:
   ├─ SSD延迟: 1-5ms
   └─ HDD延迟: 10-20ms
   
   对VR渲染的影响:
   ├─ 60 FPS = 16.67ms/帧
   ├─ 每个磁盘写入: 5-20ms
   ├─ 每帧可能有 5-10 次磁盘写入
   ├─ 总延迟: 25-200ms > 16.67ms
   └─ 结果：严重掉帧和卡顿 ❌❌❌

═══════════════════════════════════════════════════════════════════════

解决方案 ✅
═══════════════════════════════════════════════════════════════════════

【推荐方案 - 关闭AutoFlush + 批量Flush】

步骤1: 打开 GetEyeData.cs

步骤2: 找第175行左右，InitializeRecording() 方法内：
   
   现在写的:
   ┌──────────────────────────┐
   │ textWriter.AutoFlush = true;
   └──────────────────────────┘
   
   改为:
   ┌──────────────────────────┐
   │ textWriter.AutoFlush = false;
   └──────────────────────────┘

步骤3: 找第199行左右，同样操作：
   
   现在写的:
   ┌──────────────────────────┐
   │ eye120Writer.AutoFlush = true;
   └──────────────────────────┘
   
   改为:
   ┌──────────────────────────┐
   │ eye120Writer.AutoFlush = false;
   └──────────────────────────┘

步骤4: 在 GetEyeData 类的任何地方添加以下代码：

   ┌────────────────────────────────────────────┐
   │ private int flushFrameCounter = 0;         │
   │                                            │
   │ void LateUpdate() {                        │
   │     flushFrameCounter++;                   │
   │     if (flushFrameCounter % 10 == 0) {     │
   │         if (textWriter != null)            │
   │             textWriter.Flush();            │
   │         if (eye120Writer != null)          │
   │             eye120Writer.Flush();          │
   │     }                                      │
   │ }                                          │
   └────────────────────────────────────────────┘

步骤5: 在Unity中重新运行，测试改进

═══════════════════════════════════════════════════════════════════════

为什么这样修复有效？
═══════════════════════════════════════════════════════════════════════

修改前的行为:
  Update 1  → WriteLine → Flush → 等待磁盘5ms ⏳
  Update 2  → WriteLine → Flush → 等待磁盘5ms ⏳
  Update 3  → WriteLine → Flush → 等待磁盘5ms ⏳
  ... (每秒120-240次)
  结果: 渲染线程完全被阻塞！

修改后的行为:
  Update 1  → WriteLine (数据写入内存缓冲区) → 继续
  Update 2  → WriteLine (数据写入内存缓冲区) → 继续
  ...
  Update 10 → WriteLine → Flush (批量写入磁盘) ⏳ (仅1次)
  结果: 渲染线程 90% 的时间都在继续工作！

其他优化建议
═══════════════════════════════════════════════════════════════════════

进阶优化（如果仍有性能空间）:

1. 降低眼动采样率:
   if (frameCounter % 2 == 0) {
       textWriter.WriteLine(...);  // 从120Hz → 60Hz
   }

2. 异步写入（高级）:
   在后台线程中写入，完全不阻塞主线程

3. 批量 Neo4j 写入:
   不是每帧写入Neo4j，而是每秒批量写入

4. 选择性禁用眼动追踪:
   测试时可以关闭眼动追踪，只在必要时启用

═══════════════════════════════════════════════════════════════════════

总结
═══════════════════════════════════════════════════════════════════════

问题:  GetEyeData.cs 中 AutoFlush = true 导致频繁磁盘同步I/O
根因:  每秒200+次的同步磁盘写入阻塞了渲染线程
解决:  改为手动Flush，批量写入（3行代码改动）
效果:  预期性能提升 3-4倍，FPS 从15-20提升到50-60

实施难度: ⭐ (非常简单)
预期效果: ⭐⭐⭐⭐⭐ (显著改进)
